# 搭搭加载优化验收

平台：macOS / Darwin arm64。本轮目标是减少系统和数据加载等待，保留原有三维画质与功能。实际部署结果以本文件末尾及发布清单为准。

## 已落地的变更

- 对象存储 SDK（负责读写图片文件的连接客户端）按完整连接配置与进程复用；独立 Session、构造锁，派生进程重新建立连接。S3 模式在服务就绪前通过后台线程预热客户端，构造不读取对象或创建存储桶。采用 [AWS 官方客户端并发规范](https://docs.aws.amazon.com/boto3/latest/guide/clients.html#multithreading-or-multiprocessing-with-clients)，并以本地线程、配置隔离与派生进程清理回归互证。
- 试穿结果只在当前账户会话内缓存原始压缩字节，最多 2 分钟 / 32 MiB；不写入浏览器持久化存储。页面卸载仍撤销 Blob 临时地址；账户/令牌/来源版本变化不能复用旧结果。
- 优先当前试穿照片，最多 2 个后台图片下载；排队取消不发请求，失败后释放队列。历史记录、原图下载、显式刷新和活动任务轮询保留。
- 公开模型使用根据 GLB 文件内容计算的摘要版本地址和长期 HTTP 缓存；文件变化后构建生成新地址，未携带正确版本的地址不使用长期缓存。

## 画质保护

`quality-guard.json` 确认：68 个公开资源逐字节未变；三维场景相对已验证版本仅修改导入名称与 fetch 的版本地址。几何、贴图分辨率、材质、灯光、阴影、像素比、镜头、手机端既有选择规则、PNG/视频导出代码均保持原样。

## 基线与测量方法

- 只读演示账户、GET 请求，凭据仅在诊断进程内存中使用，不输出或存入日志。
- 5 张历史原图共 1,213,869 字节。旧版本通过客户端路由离开并返回，服务日志确认重复读取原图 5 次。
- 同一环境第一次存储 SDK 构造记录约 3.3 秒，随后每次重新构造仍约 10–20 毫秒；新实现同进程复用约 0.01–0.4 毫秒。冷初始化仍有成本，由启动预热承担；不得将复用耗时冒充首次初始化耗时。
- 构建期间及其他本机任务高负载时，API 与整页耗时明显波动；不同负载阶段的单次耗时不能当作固定加速比例。

## 测试与范围

- 前端相关 12 文件 130 项通过（核心 86、缓存/取消 5、相邻页面复查 39）；类型检查通过；Lint 无错误，存在原有警告。
- 后端 129 项相关 API/存储隔离测试通过，0 失败/错误/跳过；一次性 PostgreSQL/Redis/内部网络已清理。新增启动预热测试与存储测试共 36 项通过（35 项与前述测试重叠，不重复计数）。
- 一次并行全量前端运行出现多项长耗时失败后中止，退出码 130，不能作为全量通过证据；对应 3 文件已在单进程复查中全部通过，共 39 项。
- 独立只读代码审查未发现可确认 P1/P2，另行复核了启动预热；见 `REVIEW.md`。
- 本轮未触发新的付费试穿/图生视频，不把未重新调用的模型服务声称为本轮端到端生成已验收。

## 已知边界

- 高清模型首次下载及 GPU 纹理解码仍有成本；本轮没有降低任何画质参数。
- 本机其他高负载程序会影响整页耗时，本轮未关闭或修改其他项目。
- 按颜色选衣依赖已有颜色标签；提取件名字含“粉色”而没有颜色标签时，简短颜色指令不会自动推断颜色。完整衣物名称可以正常选中，此既有匹配代码本轮未修改。
- 未声称全量前端套件通过；本轮已通过的是 130 项相关前端回归、129 项后端集成与 1 项新增启动预热回归。
- 本轮未提交或推送 Git；保留用户既有工作区变更。
