## 确认并修复的问题

工作室创建搭配时，所选衣物已经验证账号归属，但独立的 `source_item_id` 外键（数据库中指向来源衣物的引用）没有相同验证。

| 输入 | 修复前真实 PostgreSQL 行为 | 修复后 |
|---|---|---|
| 来源衣物不存在 | INSERT 触发外键异常，接口未按业务错误处理 | `403`，`OUTFIT_ITEM_OWNERSHIP`，不新增搭配 |
| 来源衣物属于另一账号 | 接口返回 `201` 并保留跨账号引用 | `403`，`OUTFIT_ITEM_OWNERSHIP`，不新增搭配 |
| 来源衣物属于当前账号且在已选列表中 | 正常创建 | 保持正常创建，不重复添加衣物 |
| 来源衣物属于当前账号但未在已选列表中 | 正常创建 | 保持正常创建，保留来源且不扩展已选列表 |

修复仅在 `StudioService.create_from_scratch` 中复用既有 `validate_item_ownership` 检查来源引用，沿用现有所有权错误契约；没有修改数据库 Schema（表结构）、迁移、接口字段、权限模型或依赖。`backend/tests/test_studio_source_ownership.py` 增加 4 项可复现接口回归。工作进程没有直接调用该方法，部署由主任务统一处理。
